# Design App

This is a 2D vector based design app for web and desktop (via web view).

The frontend is React, the backend is Rust (via WASM). It uses WebGPU through the `wgpu` package, and uses `vello` for 2D rendering.

## Development

1. Build the Rust code and compile the WASM + bindings. [Check README in renderer](crates\renderer\README.md) for commands.
1. Run the web app: `pnpm start:web`

## How it works

Start from the `lib.rs` file, that's the root for any WASM module. From there, check the imported modules (aka `mod` on top) and look for the `#[wasm_bindgen]` macro. Those are structs and functions that will be exposed to JS side. These get exported to WASM and JS when we run the `cargo build` and `wasm-bindgen` CLI command. If you want to visualize what's exported from Rust, run the build process and [check the WASM build folder](crates/renderer/pkg). It should contain a `.js` and `.d.ts` file with the Rust structs and functions.

Specifically we export the `DesignRenderer` struct and a few underlying methods (like a function to initialize it, or to run the render loop). You can see an example of the struct in use [inside the web app](apps/web/src/App.tsx). It's nothing too wild, just loading and initializing the WASM (using the nice `init()` method generated by the `wasm-bindgen` CLI), and then using the structs and functions inside it (like `DesignRenderer` in our case).

The `DesignRenderer` handles rendering designs to the provided `<canvas>`. It keeps the renderer backend initialized inside, which resources for and instances of WebGPU (`wgpu`) and Vello (`vello_gpu`). And it also hold any necessary app state, like the "layers" with design data.

The `DesignRenderer` gets initialized using the `create()` method (see example linked above) and then we run a `requestAnimationFrame` loop that handles "animating" the canvas. This allow us to draw a frame 60+ FPS and handle things like a user draggingg an object, or animating design elements.

The user controls the design by sending commands (aka `DesignCommand`) to WASM backend via the `DesignRenderer.dispatch()` method. These commands range from adding or selecting a specific object/layer, or exporting the canvas data as an image.
